Every promotion of code into the `test` branch gets one row BEFORE Ofek pushes. Rules lived in
`DaraReports/specs/ENV_AND_PIPELINE_2026-07-23.md` §4: cherry-pick squash-commits only, migrations in
order + paired dump, test ⊆ dev, no test-only commits. **Superseded 2026-07-30**: promotion is now
fast-forward-only (`git merge --ff-only`), not cherry-pick — see `rs-intelligence-infra/DEV.md`
§PROMOTION POLICY for the current rule. `test ⊆ dev`, migration ordering, and "paired dump for data
promotions" still hold.

> **Machine ledger note (2026-07-30):** every green CI-driven deploy now appends its own row to
> `dara-v2`'s orphan **`ci-ledger`** branch (`LEDGER.md`), format
> `| date (UTC) | env | sha | ui_sha | sv_tag | run_url | via |` — written automatically by the
> Actions bot on every green deploy. `via` is one of `auto` (a normal green-tag push), `patch:<tag>`
> (an Ofek `patch-*` override — visually distinct in that column), or `redeploy` (a redeploy-by-tag
> re-ship, no rebuild). That ledger is the **machine** record of what got deployed, when, by which
> CI run.
>
> **This file (`PROMOTIONS.md`) remains the HUMAN ledger** — promotion *decisions*, dumps, and
> reasoning, written by hand before Ofek pushes. The two never merge.
>
